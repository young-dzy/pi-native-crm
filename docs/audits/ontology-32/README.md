# Ontology Lite — contrato #32

A fonte é a auditoria [#31](../ontology-31/README.md), ancorada em `1c9f78528571bc28ee1e009378d1bf6361c21a0b`. `lib/ontology/catalog-v1.ts` declara metadados, não fatos de clientes. O snapshot JSON contém exclusivamente definições sintéticas, sem PII. A lista física e os vínculos de ações são allowlists deliberadamente pequenas; a referência `crm_update_lead` é conferida contra o catálogo e handler MCP em teste; para acrescentar campos ou FK, comprovar origem e atualizar catálogo, validação e testes. `crm_tasks` vem da migration 0210, pois ainda falta nos types gerados.

A relação negócio → contato tem FK nullable; o inverso é 0:N. A consulta deve listar todos; roteamento de atividade usa `resolveActiveLeadForContact`, que pode escolher entre múltiplos por pipeline/atividade e recusa empate ou zero abertos. Não se pode presumir que este critério resolve toda pergunta. A relação task → contact tem defeito medido de integridade entre organizações em #31. **Nenhuma relação autoriza acesso**: #33 deve validar organização confiável e visibilidade nos dois extremos, inclusive relações opcionais e service role, e recusar dados inconsistentes.

Métricas comerciais são proposed ou unanswerable. Alto valor exige limiar ou percentil, moeda, âmbito e período; follow-up válido exige definição de canal, direção, entrega, ator e janela. O radar existente não é automaticamente a definição comercial. Valores nulos não são zero; moedas não são somadas sem câmbio autorizado. Certificação exige origem humana, revisão com identidade, data, evidência e versão exata, sem dependências faltantes; todas as dependências transitivas também devem ser certificadas e válidas; origem model só admite proposed. Esta validação é estrutural: strings de revisão não provam identidade nem autorização. Nenhum fluxo de certificação, armazenamento de revisão ou autenticação de revisor foi implementado; um consumidor não deve confiar em catálogo arbitrário como registro de aprovação.

## Versões e operação

`ontologySnapshot` captura catálogo, contrato, versão e SHA-256 canônico. `getOntology` carrega snapshot publicado por versão e confere hash; `resolveReceipt` exige versão e digest correspondentes, recusa versão desconhecida, e permite que um Run futuro recupere a definição antiga. `diffOntology` retorna caminhos alterados, sem dados de clientes. Para publicar nova definição, acrescentar snapshot imutável e registro, testar compatibilidade; rollback consiste em selecionar uma versão publicada anterior para novos consumidores, sem reescrever recibos antigos. A biblioteca não persiste seleção ativa, não executa deploy/rollback e não altera Runs existentes. Se o snapshot histórico mudar, seu digest deve permanecer registrado independentemente no recibo; o registro local detecta alterações inconsistentes com o digest do snapshot, não uma adulteração coordenada de ambos.

`ontologyCacheKey` inclui digest, versão, escopo confiável e revisão de configuração; mudanças produzem chave diferente. Não há cache, invalidação distribuída ou mecanismo de revisão de configuração instalado. Consumidor futuro deve gerar revisão monotônica ou hash confiável, incluir identidade/visibilidade relevantes no escopo, impedir reuso após revogação e definir TTL/evicção. A chave não é autorização.

## Auditoria de configuração

`organizations.settings` é JSONB existente. `app/api/v1/settings/routing/route.ts` usa `requireRole("manager")`, valida schema, lê e grava por admin client com filtro explícito da org e registra `routing.config_changed`; mescla chaves existentes. É um precedente possível, não implementação de configuração ontology: leitura seguida de escrita sem controle de versão pode perder mudanças concorrentes, o audit é assíncrono e não é histórico transacional de versões/rollback. Não existe limiar de alto valor aprovado aqui. Antes de usar settings para este propósito, definir schema, autorização, superfície para leitura/edição, concorrência, revisão auditável, invalidação e recuperação. Até lá exigir parâmetros explícitos e esclarecer sua origem.
